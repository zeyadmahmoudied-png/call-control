## Design decisions
- Domain knows nothing of storage. Storage ports live in `storage-core`; Room/DataStore implement them.
- Number rules and schedule windows: Room. Everything simple (control on/off, global mode, unregistered/hidden
  levels, schedule on/off and default mode, theme, onboarding): DataStore.
- Unique index on the normalized number; the Repository normalizes first, so `010...`, `+2010...`, `002010...` collide.
- Modes are stored as enum names, not ordinals. Rows with an unknown mode are skipped, never deleted.
- No destructive migration and no code that deletes the database file. Unmigratable schema => open fails =>
  Repository reports failure => the (Phase 3) service must fail open. `MIGRATIONS` is empty at version 1.
- Failures: every storage exception becomes `RepoResult.Failure(Storage(<class name only>))`; messages (which
  could contain numbers) are dropped. Cancellation is re-thrown. No logging of numbers anywhere.
- `loadRuleConfig()` is all-or-nothing: partial rules are never used.
- DataStore read errors are not masked as "defaults" (would risk overwriting a real file).
